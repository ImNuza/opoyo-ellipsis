What this is

OPOYO is a floor-vibration fall detector. The product is a piezo puck bonded to a slab. This build is the proxy: iPhones on the floor send user-acceleration and a sound-level number to a Mac dashboard.

How the pipe works

  1. Each phone samples CoreMotion user-acceleration at 50 Hz and microphone RMS as dB.
  2. A JSON packet goes over UDP to the Mac on port 9000. Audio samples never leave the phone. Only one dB number does.
  3. The Mac keeps up to five phones, keyed by a UUID created on first launch.
  4. This page shows the combined floor, then one screen per phone so a judge can see that each device is sending.

Formulas

User acceleration is gravity-removed, in g.

mag = sqrt(ax² + ay² + az²)

dB = 20 · log10(max(rms, 1e-8))

Combined magnitude at a tick is the maximum mag among phones that sent a packet in the last 2.5 s. Combined sound is the maximum dB. Axes are not averaged. Each phone has its own heading.

Identity

A phone is not identified by MAC address. iOS will not give that to the app. The stable key is a UUID stored on the phone. The card also shows the model and a four-character short id. Rename on the dashboard is stored on the Mac against that UUID, so quit and rejoin keep the name.

Live rule (Mac, not the browser)

Detection runs in server/detect.py on the combined magnitude stream. The page only displays state. CS can replace Detector.tick later with a model that emits the same FallEvent.

FallEvent: id, t0, peak_g, rise_ms, decay_ms, node_id, state

state: quiet → suspect → recovered | cancelled | confirmed

  1. Peak: combined mag ≥ FUSION_PEAK_G (default 0.4 g) for at least 2 samples.
  2. Rise: quiet to peak ≤ FUSION_RISE_MS (80 ms). Slow sits fail this.
  3. Decay: after peak, mag falls below quiet in 150–400 ms and stays there for 80 ms. Periodic hops fail the hold.
  4. Suspect starts a 10 s demo clock (product copy is 60 s). Banner: “Suspect · 10 s to confirm”.
  5. Extra mag ≥ 0.15 g after 500 ms → recovered. Cancel on this page → cancelled. Neither → confirmed.

If a book still pages, raise FUSION_PEAK_G until the book is quiet and a knee-drop still fires. No acoustic veto in this slice.

Telegram

One-way alerts. The floor phone is the puck, not grandpa. Cancel is on this Mac.

  • t+0 on suspect: “possible fall. Node {name}. Cancel on the Mac.”
  • t+10 on confirmed: “no recovery, still down.”
  • Recovered or cancelled: silence.
  • Target chat is TELEGRAM_TARGET in .env (hackathon group when set to family).

Phone keep-awake

iOS will not stream CoreMotion or mic in the background. Streaming turns the idle timer off. A Keep screen awake toggle keeps it off after Stop. That is the Friday path: face-down, screen on.

Limits

  • This is a phone-on-tile proxy, not a bonded piezo.
  • Campus Wi-Fi often blocks phone-to-laptop UDP. Personal hotspot is the trusted demo network.
  • A sixth phone is dropped.
  • No labelled fall corpus. The live path is a kinematic rule, not a trained classifier.
  • Thresholds must be calibrated on the demo tile. Defaults are a starting point.

Tweak (CS)

Env knobs, then restart uvicorn: FUSION_PEAK_G, FUSION_QUIET_G, FUSION_RISE_MS, FUSION_DECAY_MIN_MS, FUSION_DECAY_MAX_MS, FUSION_DECAY_HOLD_MS, FUSION_RECOVER_G, FUSION_RECOVER_AFTER_MS, ESCALATE_S.

Code: server/detect.py (rule), server/notify.py (copy + chat), tests/test_detect.py (knee vs book vs sit). Swap later: same FallEvent, disagree with the rule → no Telegram.
